# Contributing

Thanks for helping improve NuttyMod Loader for The Cube Beta. Contributions may include add-ons, catalog corrections, documentation, bug fixes, and loader improvements.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md) and [Community Guidelines](COMMUNITY_GUIDELINES.md).

## Before starting

1. Search open issues and pull requests to avoid duplicate work.
2. Open an issue before a large or breaking change so the approach can be discussed.
3. Fork the repository and create a focused branch from the main branch.
4. Do not include credentials, personal information, generated clutter, or unrelated changes.

## Making a contribution

- Keep each pull request focused on one purpose.
- Follow the existing directory and naming conventions.
- Write clear commit messages that describe the result.
- Test the behavior you changed and explain how you tested it.
- Update documentation when installation, behavior, compatibility, or the catalog format changes.
- Preserve attribution and include the license for third-party work.

Only Python (**.py**) and Ruby (**.rb**) add-ons for The Cube Beta are accepted. For add-on submissions and updates, follow every requirement in [Publishing Add-ons](PUBLISHING_ADDONS.md).

## Pull requests

A useful pull request includes:

- a short explanation of the problem and solution;
- links to relevant issues;
- testing steps and results;
- screenshots or logs when behavior is visual or difficult to reproduce; and
- any compatibility, security, migration, or save-data impact.

Mark incomplete work as a draft. Be responsive to review comments, and resolve conversations only after the concern has been addressed or agreed upon. Maintainers may close inactive, duplicate, unsafe, out-of-scope, or noncompliant submissions.

## Issues and bug reports

Before opening an issue, verify that it has not already been reported. Include:

- a descriptive title;
- the game, loader, operating system, and add-on versions involved;
- exact steps to reproduce the problem;
- expected and actual behavior; and
- relevant logs with secrets and personal information removed.

Do not use public issues for suspected vulnerabilities, malicious packages, harassment reports, or other sensitive matters. Follow the private reporting process in the [Code of Conduct](CODE_OF_CONDUCT.md#reporting-a-problem).
